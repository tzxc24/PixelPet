# 硬件到货调试手册

全表现场步骤为 **HW_PENDING**。第一步是只连接主控 USB、识别板号和串口，保持外设门控禁用。将板载标记与 ESP32-S3 N16R8 的购买资料比对。引脚、供电核对见同目录 GPIO 文档。

```powershell
Set-Location D:\PixelPet
Get-CimInstance Win32_SerialPort | Select-Object DeviceID,Name
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\build.ps1
# 在确认开发板、端口和写入范围后选择对应模式，再执行：
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\build.ps1 -Action menuconfig
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\build.ps1 -Action flash -Port COM7
powershell -NoProfile -ExecutionPolicy Bypass -File firmware\build.ps1 -Action monitor -Port COM7
```

COM7 只是示例，监视器 Ctrl+] 退出。选择 `PixelPet firmware → Boot mode`；改模式后用上述构建或 flash 命令重新构建。保留 NVS 备份，现场步骤不需要全片擦除。启动失败先读串口日志、核对芯片/串口和稳定供电，按目标板说明进入下载模式，然后重新烧录正确版本。

| 顺序 | 模式与成功现象 | 失败时检查 |
|---|---|---|
| 1 | serial and PSRAM probe。看到串口日志、PSRAM 堆总量和 16 KiB 内存读写测试结果 | USB 数据线、串口权限、PSRAM 模式、板号；此探针只抽样，整颗 8 MB 稳定性须板测 |
| 2 | ST7789 color bars。四色正确、240×240 无偏移 | SPI 次序、屏幕 VCC、BL、CS-F、面板色序 |
| 3 | ST7789 local animation。约 4 秒局部眨眼及嘴部变化 | SPI DMA、图块边界、传输超时；这是独立测试，不代表语音嘴型同步 |
| 4 | INMP441 capture peak。采样数与峰值随声音变化 | L/R 槽、BCLK/WS、供电和对齐 |
| 5 | MAX98357A low-amplitude test tone。短暂低幅音后静音 | SD/MODE、24 kHz I2S 槽、跨接喇叭、供电 |
| 6 | TTP223 state transitions。按下和松开日志与动作对应 | 极性、模式跳线、防抖、共地 |
| 7 | one 70 ms MOS motor pulse。仅有一次受控脉冲 | 测量驱动阈值、供电压降及默认关断，核对保护与地线 |
| 8 | Wi-Fi association only。STA 成功关联并取得地址后停止 Wi-Fi | 2.4 GHz、SSID、口令、WPA2 与 DHCP |
| 9 | PixelPet WebSocket networking。未开启外设门控时可独立验证控制握手、心跳和断线恢复 | PC 地址、端口、Host 白名单、Bearer 与 CA；检查隔离局域网 |
| 10 | 电气确认后使用语音模式，按触摸录音、上传、播报、跨轮记忆的顺序测试 | 校验会话、帧序号、PCM 格式、ASR/模型/TTS 耗时，观察掉线和取消 |
| 11 | 记录屏幕状态、实际唇形和马达联动 | 当前独立测试模式与网络状态已分开，实时端侧联动仍需补齐 |

所有 GPIO 输出模式均沿用 `hardware/pinmap.json` 安全门控。Wi-Fi-only 只需要 NVS 中的 SSID 和口令，WS 测试还需要 PC 主机、端口、设备专用令牌和安全传输配置。NVS 字段、有效范围与证书注意事项见 `firmware/pixelpet_s3/README.md`。Wi-Fi、WebSocket、音频和屏幕高频联调时，记录最小剩余任务栈、可用内部堆和 PSRAM，观察串口复位原因。
