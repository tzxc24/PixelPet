# SQLite 手动备份与恢复

从 `D:\PixelPet` 运行。默认使用现有后端配置定位数据库，SQLite 在线备份接口会纳入已经提交的 WAL 内容。新备份生成到 `output/backups`，通过完整性检查后才报告成功。

```powershell
.\.venv\Scripts\python.exe scripts\backup.py
.\.venv\Scripts\python.exe scripts\backup.py --check output\backups\YOUR-BACKUP.sqlite3
.\.venv\Scripts\python.exe scripts\backup.py --restore output\backups\YOUR-BACKUP.sqlite3 --destination output\restored.sqlite3 --confirm-restore
```

将示例备份文件名换成实际值。恢复需要显式确认，目标必须在项目内且文件和 SQLite sidecar 均不存在。原数据库可以保留。停止 PixelPet 后，将现有配置的 `PIXELPET_DATABASE_PATH` 指向已检查的恢复文件，再启动并核对会话和记忆。回退时停止服务并将配置改回原路径。备份包含私人聊天和记忆，保留在本机，不放入源码交付包。

自动化测试用隔离的临时 SQLite 文件验证完整性、损坏备份拒绝、恢复确认、恢复内容和拒绝覆盖。现有 API 测试通过实际 SQLite 重建应用并在新会话检索记忆，模型部分为 Mock。真实 DeepSeek 链路另见设备语音验证报告。
